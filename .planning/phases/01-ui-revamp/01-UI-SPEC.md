# Phase 1 — UI Design Contract: AstroVetro V1 Complete Creative + UI/UX Revamp

> Visual and interaction contract for the AstroVetro v1 revamp. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Source authority:** This contract is driven by the client's creative brief ("ASTROVETRO V1 — COMPLETE CREATIVE + UI/UX REVAMP") plus verified codebase data. The brief is unusually prescriptive; upstream artifacts (CONTEXT.md / RESEARCH.md / REQUIREMENTS.md) were **not present** in `.planning/`, so the brief's locked decisions stand as the contract defaults. Real business data is pulled from `src/data/*` and must not be overwritten.
> **Implementation status (2026-08-31):** Full UI contract implemented across `src/` (design tokens in `index.css`, all 15 section components rewritten, new `BrandStatement` + `VisualInterlude`, new `Navbar` with full-screen mobile menu, new palette/typography/radius/motion system) and committed in git (`cbb64db`, `b583937`, `91889f3`). **Imagery:** this environment provides no native image-generation capability; the turnkey pipeline is in place — a complete per-asset prompt set (`IMAGERY.md`) + `scripts/generate-images.mjs` (`npm run images`) that converts 4K+ source photography dropped into `public/images-src/` into the AVIF/WebP/JPEG derivatives the wired `<picture>` components serve automatically. Until real photography is generated, premium art-directed SVG scenes render as graceful fallbacks (no empty slots). See "Imagery Requirements" below.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** (bespoke Tailwind v4 CSS-first system; no shadcn) |
| Preset | not applicable |
| Component library | none (hand-rolled editorial components) |
| Icon library | none (minimal inline SVG / unicode arrows only — avoid icon-library look) |
| Font | **Instrument Serif** (display, serif) + **Manrope** (sans) — already configured in `@theme` |
| Styling | Tailwind v4 CSS-first `@theme` tokens in `src/index.css` |
| Animation | framer-motion v13 (already a dependency) |

**Why not shadcn (gate decision):** The brief explicitly forbids a generic "AI-generated template" look, "excessive rounded rectangles," and "overuse cards." shadcn's component conventions directly conflict with the required bespoke luxury-editorial art direction. The project already ships a Tailwind v4 CSS-first token system (`@theme` in `index.css`) that suits a custom design better than shadcn's config-based preset. `components.json`, `tailwind.config.*`, and `postcss.config.*` are all **absent**, confirming the CSS-first approach is the established convention. **Decision: Tool = none.** No registry safety vetting required.

**Color policy — one field per section (rhythm, not rainbow):** Each major section uses a **single large colour field**, not every colour at once. The page moves through deliberate blocks — IVORY (hero) → SKY (manifesto) → SOLAR (intention) → IVORY (featured) → IVORY (collection) → DEEP INK (science) → MINT (interlude) → IVORY (pivot) → PEACH (readings) → LAVENDER (footer) — creating visual rhythm. Accent (10%) is reserved for targeted emotion/discovery moments only.

**Accent reserved for (explicit list):**
- Intention discovery: active-intention highlight (`#FFE66D` field), hover colour wash, matching-product preview
- Headline keyword emphasis (e.g. "FOR YOU.", "THE STARS.", "ENERGY.")
- Fine editorial rules, section numerals (`text-section-num` at 4–6% opacity), micro-metadata
- CTA hover accent (one accent per button hover, not multi-colour)
- Category differentiation cues in the collection

**Rule:** "Do not dump every colour onto the page." Body, headings, buttons and layout surfaces stay ivory/ink. Each section shows one dominant field + ink text + a single accent moment. No rainbow sections.

### Typography

| Role | Font Family | Sizes (px) | Weight | Line Height |
|------|-------------|-----------|--------|-------------|
| Display | Instrument Serif | 96, 72, 56 | 400 (regular) | 1.0–1.05 |
| Heading | Instrument Serif | 40, 32 | 400 | 1.1 |
| Subheading | Instrument Serif *italic* | 28 | 400 | 1.2 |
| Body | Manrope | 16, 18 | 400 | 1.5 |
| Lead | Manrope | 20 | 400 | 1.5 |
| Label / Caption | Manrope | 12, 14 | 500 | 1.4 |
| Micro-metadata | Manrope | 10–11 | 500 | 1.3, letterspacing 0.18em, uppercase |

**Rules:**
- Exactly 2 weights max: **400 (regular)** and **600 (semibold)**. Use 600 sparingly (CTAs, labels). Never use 700+.
- HUGE serif statements with very little copy per section (luxury-magazine feel, not dashboard).
- Body max-width ~60–70ch. Prefer narrow editorial columns over wide paragraphs.
- Avoid: excessive uppercase, tiny captions everywhere, inconsistent sizes. Uppercase reserved for micro-metadata and CTAs.

### Spacing Scale (multiples of 4)

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Card padding, inner section gaps |
| xl | 32px | Layout gaps, feature blocks |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |
| 4xl | 96px | Big section rhythm (only desktop) |
| section-y | 120px (desktop) / 72px (mobile) | Vertical padding of major `<section>` elements |

Exceptions: icon/touch targets on intention explorer ≥ 44px tap area; hero uses asymmetric large whitespace (see Layout) — not a uniform spacing box.

### Border Radius System

Adopt **minimal, architectural radii** — not bubbly rounded rectangles.

| Token | Value | Usage |
|-------|-------|-------|
| `--radius-none` | 0 | Editorial grid frames, full-bleed imagery, architectural crops |
| `--radius-sm` | 4px | Small chips, buttons (small) |
| `--radius-md` | 8px | Cards, image frames |
| `--radius-lg` | 16px | Large image frames only |
| `--radius-full` | 999px | Pill buttons |

**Rule:** Prefer **0–8px** for most surfaces. Reserve large radii (16px / full) for select moments. Avoid rounded-everything.

### Shadows / Elevation

| Token | Value |
|-------|-------|
| `--shadow-soft` | 0 1px 2px rgba(24,24,23,0.04), 0 8px 24px rgba(24,24,23,0.05) |
| `--shadow-lift` | 0 2px 6px rgba(24,24,23,0.06), 0 24px 64px rgba(24,24,23,0.10) |
| `--ring-ink/5` | Thin 1px hairline borders (`border-ink/8`) for frames |

### Motion / Timing

| Token | Value |
|-------|-------|
| `--ease-out-expo` | cubic-bezier(0.16, 1, 0.3, 1) |
| Standard reveal | 0.9–1.4s ease-out-expo |
| Hover | 0.3s ease |
| Stagger | 0.08–0.12s per child |
| Parallax | gentle, ≤ 20% of scroll delta |

**Motion mood:** CALM, PRECISE, LUXURIOUS, INTENTIONAL. Not fast, not gamified, not neon, not distracting. **Must** respect `prefers-reduced-motion` (framer-motion `useReducedMotion` + CSS reduce block already present in `index.css`).

## Layout / Grid System

### Breakpoints

| Breakpoint | Width | Notes |
|------------|-------|-------|
| Mobile | 375, 390, 430px | Intentionally composed, no overflow |
| Tablet | 768 | Split layouts begin |
| Laptop | 1024 | Editorial columns |
| Desktop | 1280, 1440 | Expansive |
| Wide | 1920 | Full-bleed interludes, 12-col grid |

### Grid

- **Editorial grid:** 12-column max-w-7xl (~80rem) container, generous gutters (px-6 mobile → lg:px-10). Thin 1px grid lines at very low opacity (`ink/5–/8`) as an **architectural drafting / scientific observation background** in selected sections only. It must support composition, never dominate.
- Sporadic **micro-metadata**: `01`, `02`, `03` and `ASTROVETRO / 01`, `COLLECTION / 02` numerals in micro-uppercase — used sparingly, top corners of sections.
- **Vary layout rhythm per section** — banned pattern = "heading + three cards + three cards + button." Use instead: asymmetric grids, split-screen stories, full-bleed photography, oversized typography, overlapping imagery, narrow editorial columns, large product showcases, horizontal-scroll strips, full-bleed interludes.

| Service/reading | 3:4 portrait |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (products) | **Explore the Collection** |
| Secondary CTA (services) | **Explore Readings** |
| Product card CTA | **Explore** |
| Reading card CTA | **Book a Reading** |
| Featured product CTA | **View Crystal** / **Shop Now** |
| Final CTA | see below |
| Hero headline | "Find what feels like you." (or better, short) |
| Hero supporting | One–two sentences explaining AstroVetro |
| Intention prompt | **"What are you looking for?"** |

**Empty state (collection filter):** if an intention reveals no products → heading `Nothing here yet` / body `No products match this intention. Choose another to explore.` with a `Reset`/`Show all` affordance. (All 8 intentions map to real products today, so this is a defensive state only.)

**Error state (imagery):** product/service with no image file falls back to the existing **SVG photographic scene** (`visual/*`), never an empty/blank slot. Caption: `Image coming soon` (subtle). If the file is present, show the photograph.

**Destructive actions (this phase):** none destructive in the public UI (no account deletion, no irreversible flows in scope). If a cart-remove or checkout-cancel is added by a later phase, it requires a confirmation prompt: `Remove from bag?` → `Remove` / `Keep`.

**Final CTA:** strong closing conversion (e.g. `Start your journey` / `Explore the collection` + booking path). Keep positive and specific.

## Conversion Strategy

Every major section has a purpose. Funnels:

- **Product:** Hero → Discovery → Product → Product detail → Purchase
- **Service:** Hero → Guidance → Reading → Booking

Trust section communicates only supported claims: thoughtfully selected, carefully packaged, secure checkout, transparent info, personal experiences. **No** invented certifications, sourcing claims, customer counts, guarantees, or reviews.
